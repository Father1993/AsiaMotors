# Проверка выпуска админки

Проверки выполняются на отдельном Docker Compose проекте и синтетических данных.
Production `.env`, ключи и пароли не выводятся и не входят в образы.

## Команды

```sh
docker compose -p asiamotors-test -f compose.yaml -f compose.test.yaml up -d --build --wait
npm run typecheck
npx playwright test
python3 tests/admin-api.py
python3 tests/selfhost-integration.py
python3 tests/mail-disabled.py
sh tests/backup-restore.sh
```

Тестовый SMTP — только локальный `smtp` из `compose.test.yaml`. Проверка
`mail-disabled.py` временно выключает тестовый worker и задаёт недоступный SMTP;
она требует сохранения заявки с `pending:0`, затем возвращает локальный SMTP.
`selfhost-integration.py` оставляет одну синтетическую машину для проверки
перезапуска/резервного копирования. Скрипт восстановления создаёт отдельную
временную БД и сравнивает все строки и содержимое архива фотографий.

Проверки миграций и очистки медиа используют приложение PostgreSQL на локальном
порту 35432 и отдельные SQL-схемы:

```sh
PGHOST=127.0.0.1 PGPORT=35432 POSTGRES_USER=postgres \
POSTGRES_PASSWORD_FILE="$PWD/.secrets/db_admin_password" node tests/car-publication.mjs
PGHOST=127.0.0.1 PGPORT=35432 POSTGRES_USER=postgres \
POSTGRES_PASSWORD_FILE="$PWD/.secrets/db_admin_password" node tests/car-drafts-migration.mjs
PGHOST=127.0.0.1 PGPORT=35432 POSTGRES_USER=postgres \
POSTGRES_PASSWORD_FILE="$PWD/.secrets/db_admin_password" node tests/media-cleanup.mjs
```

## Подтверждённые результаты

- Production Docker build и TypeScript проходят; административные файлы без новых ошибок ESLint.
- Девять браузерных сценариев Chromium проходят на собранном Docker-образе:
  черновики, публикация, скрытие, фото и повтор загрузки, восстановление формы,
  конфликт вкладок, истёкшая сессия, потеря ответа POST, уход во время сохранения,
  фильтры/пагинация/ошибки списка, публичные маршруты на 390/768/1440 px.
- API проверяет права и источник, поля черновика/публикации, версии, повтор создания,
  сохранность фото, фильтры/пагинацию, старые ссылки 308 и скрытые страницы 404.
- Заполненная БД проходит миграцию с сохранением данных; повторный запуск безопасен.
- Очистка фотографий сохраняет файлы черновиков/скрытых машин и учитывает конкурентное сохранение.
- Заявки, согласие, защита от повторов, очередь и восстановление после сбоя тестового SMTP проходят.
- При выключенной почте заявка остаётся в БД с нулём попыток SMTP.
- Восстановление dump и архива фото воспроизводит исходные данные и файлы.
- Образ запускается с UID 1000 и не содержит `.env`, `.secrets` или тестовых фотографий.
- `npm audit --omit=dev` не обнаружил известных уязвимостей на момент проверки.

Проверка экранной клавиатуры и выбора фото на физическом телефоне остаётся
отдельной пользовательской приёмкой. Эмуляция размеров её не заменяет.
Активация production подтверждается только после интерактивного запуска
`scripts/deploy-admin.sh --without-mail` и проверки работающего VPS.
